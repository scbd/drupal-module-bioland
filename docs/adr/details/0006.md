# 0006 details — theme authority

## Considered Options

- Keep theme in dmsm's JSON5 config and add a Drupal-side editor that writes back to dmsm.
  Rejected: dmsm exposes no write API to the module today; this would need new cross-repo
  plumbing for an authority Drupal already owns for `biolandSettings`.
- Let the head-side config-endpoint registry be the theme authority (that plan's Decision 8).
  Superseded: the head-side config registry keeps only the network default/fallback theme;
  `bioland.settings.theme` supersedes it as the per-site authoring authority.
- Add a Drupal update hook to eagerly seed every site's theme from dmsm on module update.
  Rejected: a new hook inherits the Search-API convergence duty pinned by
  `SearchApiConvergenceHookTest`; lazy seed-on-save avoids that coupling.

## Decision Drivers

- dmsm attaches `biolandSettings` on every request, after the public allowlist and with no dmsm
  cache: `server/api/config/[env]/[multiSiteCode]/[siteCode]/index.get.js:43-83`.
- Head camelCases the attached settings at depth 7: `server/utils/context-unified.ts:354,356`.

## Consequences

- **Lazy-seed, no update hook.** The Theme tab pre-populates from the effective dmsm theme and
  writes only on save (seed-on-save, never on GET). A site decouples from network-default drift
  only when an editor saves the Theme tab; after seeding, per-site dmsm theme edits become inert
  for that site.
- **Release note.** The 46 default-tracking sites keep live inheritance until an editor saves;
  nothing changes for them at deploy time.
- **Staleness.** The existing ≤5-minute head Nitro TTL (`context-unified.ts` `cachedFunction`) is
  the only staleness this decision accepts; no cache invalidation is built for theme saves.
- **Fall-through safety.** Until a site is seeded, precedence falls through to `config.theme` /
  `runTime.theme` / code defaults, so an unseeded site's render is unaffected by this decision.
